# TH1-1495 — cron bot-chat delivery child rebuilds a dependency generation every run (m5)

- Root cause: on v0.22.2 the cron `bot-chat` delivery (`cron/scheduler_delivery.py:_deliver_to_bot_chat`) spawns `python -m hermes_cli.main chat -Q …` every tick without `HERMES_DISABLE_LAZY_INSTALLS`; its bootstrap (`hermes_cli/venv_sync.py:prepare_launch`) finds the venv stamp stale because `pm/workspace.py:members_stamp` hashes every file under member plugin dirs and the member plugin `typesafe-skill-router` writes its runtime `cache.json` (1.6 MB) into its own plugin dir, so the child runs `sync_venv(evict_incompatible_plugins=True)` and publishes a new ~660 MB generation; `collect_generations` cannot reclaim it for 24 h.
- Evidence: 22 `~/.hermes/logs/update_receipts/pm_20261020T*-sync-<pid>-*.json` rebuild receipts on 2026-10-20 (latest 21:45:52Z), each from a distinct short-lived child PID; gateway PID 40816 env has no `HERMES_DISABLE_LAZY_INSTALLS`; read-only probe: recorded stamp 4d6c0c31… vs expected bf4d2dc0…, `venv_is_current() == False`; cron `.py` scripts already carry the flag (`cron/scheduler_script.py`).
- Upstream: the CLI delivery lane was retired on main by 0663bdf98c1 (2026-10-16, in-process `tools.bot_live_delivery`); `rc.1-v0.22.3` and the canary tags from 2026-10-20 have no subprocess lane. m5 runs v0.22.2 (d923a5eb), which still has it.
- This branch (based on v0.22.2): sets `HERMES_DISABLE_LAZY_INSTALLS=1` on the delivery child env, net-zero lines (file-size ratchet), plus `tests/cron/test_cron_bot_chat_delivery.py::test_deliver_child_runs_with_lazy_installs_off` — red on base (`KeyError`), green with the fix. `python scripts/check`: 12 checks ok.
- decided: no upstream PR — the fix target no longer exists on main and upstream cuts 0.22.3 from main (0 commits on release/0.22.2 after the tag); branch pushed to the fork as a backport-ready patch for the installed release.
