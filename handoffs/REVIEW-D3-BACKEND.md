## Findings, ordered by severity

1. **P1 — saved `auth.json` can redirect an access token to an attacker host.** `hermes_cli/nous_account.py:313` obtains the saved `portal_base_url` through `_portal_base_url(state)` (`:612-614`). `_fresh_account_info` retains it (`:367`) and `_fetch_nous_account_info` sends `Authorization: Bearer` to that URL (`:482-490`), even though `hermes_cli/auth_nous.py:215-218` now ignores saved routing metadata in the main credential resolver. Concrete trigger: a configured Envoy Portal plus an existing `auth.json` with a Nous access token and `portal_base_url: https://attacker.invalid`, followed by a forced account/entitlement lookup (`agent/credits_tracker.py:496`, `agent/conversation_loop.py:488`). In an isolated HERMES_HOME, I wrote that shape to `auth.json`, configured the Portal as `https://configured.invalid`, used the real `resolve_nous_access_token` path, intercepted `urlopen`, and observed `configured_portal_saved_attacker_request [('https://attacker.invalid/api/oauth/account', True)]`; the boolean records presence of the Authorization header without printing its value. Positive routing control with the same configured Portal and no saved URL produced `configured_portal_no_saved_route_request [('https://configured.invalid/api/oauth/account', True)]`. With the current empty manifest, the main token resolver rejects the request before this path; the saved-route failure occurs when Portal is enabled. This invalidates the blanket saved-route claim.

2. **P2 — container defaults still point to an upstream image repository.** `hermes_cli/config_defaults.py:12` sets `DEFAULT_SANDBOX_IMAGE` to `nousresearch/hermes-sandbox:desktop`; `:351,357-359` gives it to Docker, Singularity, Modal and Daytona by default. The Docker backend inserts this value in `docker run` (`tools/environments/docker.py:1007-1019`), which can pull the image on a fresh machine. Concrete trigger: choose the Docker terminal backend without explicitly setting `terminal.docker_image`. This is an upstream repository contact despite no Envoy endpoint being configured. I verified the config and command construction by code reading; I did not perform a network pull.

3. **P2 — first-time setup still selects Nous by default.** `hermes_cli/setup.py:666-670` puts “Quick Setup (Nous Portal)” first and labels it recommended; `:739-740` calls `prompt_choice(..., 0)`, so Enter selects it. `hermes_cli/setup_quick.py:97-98` invokes the Nous model flow, and `hermes_cli/model_setup_flows.py:266-274` saves provider `nous` after a successful flow. Concrete trigger: first-time interactive setup with a configured Portal endpoint, then accept the default choice. The blank `DEFAULT_CONFIG['model']` does not change this onboarding default. This is a code-path finding; I did not run interactive login.

4. **P2 — diagnostics upload can go to a config-selected host while the consent notice promises Nous-internal storage.** `hermes_cli/diagnostics_upload.py:34-36` accepts `HERMES_DIAGNOSTICS_BASE_URL`, and `:59-65` PUTs the full bundle to the response's `uploadUrl` with no destination binding. `hermes_cli/debug.py:559-575` tells the user the bundle is only available to Nous staff in internal S3. Concrete trigger: a hostile diagnostics URL in process config responds with `uploadUrl: https://attacker.invalid/collect`; after confirmation, the bundle goes there. In an isolated, intercepted run I observed a POST to `https://configured.invalid/api/diagnostics/upload-url` and PUT to `https://attacker.invalid/collect` with a nonzero body. Negative control with no endpoint raised “Diagnostics upload is disabled” before network. A configured diagnostics service may legitimately return a presigned third-party storage URL, so the destination policy must account for that; the present privacy promise is false for arbitrary configured endpoints.

5. **P2 — two outbound diagnostics User-Agent values still identify Hermes.** `hermes_cli/diagnostics_upload.py:17,22` and `hermes_cli/debug.py:29,151,172` set `User-Agent: hermes-agent/debug-share` on actual urllib requests. Concrete trigger: `hermes debug share --nous` with a configured diagnostics endpoint, or ordinary public paste sharing/deletion. The main inference attribution paths use Envoy (`agent/anthropic_adapter.py:361-364`, `agent/auxiliary_client.py:869-871,933-939`), but the claimed User-Agent coverage is incomplete.
